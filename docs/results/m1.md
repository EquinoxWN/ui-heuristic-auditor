# M1 test results

Recorded 2026-10-05 on the author's machine (Intel Core i7-13700H, Windows 11, Python 3.14.5,
Playwright 1.63.0 with its bundled Chromium, axe-core 4.13.0). CI re-runs everything on Ubuntu with
Python 3.12 and audits one real public page.

## Tests: 21 passed, 0 failed

Command: `make test` (`pytest`, real headless Chromium against a local fixture site). Run three
times after the final change; all runs passed (about 20 seconds each).

| File | Tests | What it proves |
|---|---|---|
| `test_capture.py` | 11 | Each viewport's screenshot has the viewport's width and the full page height, and the DOM is saved; the clean page has zero findings; all six seeded problems are found on exactly the seeded elements, with WCAG tags, a fix and a help link; a phone-only and a desktop-only problem are attributed only to their viewport; boxes lie inside the screenshot; severity filtering and worst-first order; `file:`, `javascript:`, `ftp:` and host-less URLs are refused; a page that does not load in time is an error |
| `test_findings.py` | 2 | The same problem at two sizes is one finding with both viewports; sorting by impact then rule |
| `test_cli.py` | 3 | The real CLI (subprocess) writes `report.json` and `summary.md`; `--fail-on` turns findings into exit 1; bad URLs and unknown viewports exit 2 |
| `test_report.py` | 2 | A hostile page title and selector (HTML tags, a `# heading`, a `javascript:` link, backticks and pipes) stay inert in `summary.md`: no raw HTML, no injected heading or link, every table row keeps five cells; code spans use a fence longer than any backtick run (added in the 2026-10-06 security recheck) |
| `test_axe.py` | 3 | The pinned axe-core was verified and cached; a tampered tarball and an unsupported hash algorithm are rejected; only `axe.min.js` is read, even when the tarball contains a `../` entry |

Lint: `ruff check`, `ruff format --check` and `mypy --strict` on 15 files: clean. Audit: `pip-audit`:
no known vulnerabilities.

## Quality control (DMAIC)

| Phase | This repository |
|---|---|
| Define | Accessibility problems are often found late, by users who cannot complete a task, and problems that exist at only one screen size are easy to miss; this affects front-end developers and QA engineers. M1 counts when Playwright captures a page at phone and desktop sizes, a verified axe-core runs WCAG A and AA rules in each, findings are merged with their element, viewports and boxes, and the CLI can fail a build at a chosen severity ([RFC 0001](../rfc/0001-design.md)). |
| Measure | `make test` (run three times after the final change, real headless Chromium against a local fixture site), ruff, `mypy --strict`, `pip-audit` and one audit of example.com, on an Intel Core i7-13700H with Windows 11 and Playwright 1.63.0. 21 tests passed, 0 failed; 6 of 6 seeded problems were found on the right elements, 2 of 2 viewport-specific problems at their own viewport only, 0 findings on the clean page; example.com was audited in 4.2 s with 0 findings. |
| Analyze | Detection on seeded fixtures shows the pipeline works end to end, not the tool's accuracy on real pages. No defects recorded. Precision and recall on a labeled set are not measured yet (M3). |
| Improve | No defect is recorded for M1. The 2026-10-06 security recheck added tests that a hostile page title and selector stay inert in `summary.md`, with code spans fenced longer than any backtick run. |
| Control | The `ci` workflow's `build` job runs `make setup`, installs Chromium with its system libraries, runs `make lint test` (ruff, ruff format, `mypy --strict` and the 21 tests), audits example.com into the job summary and runs `make audit` (`pip-audit`). In the code, only http and https URLs are audited, axe-core is pinned by version and npm sha512 and a tampered tarball raises `IntegrityError` before it runs, only `axe.min.js` is read from the tarball (ADR 0002), and only WCAG A/AA rules run (ADR 0003). |
